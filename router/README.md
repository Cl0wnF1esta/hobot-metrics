# Экспортер на отдельном всегда включённом устройстве

## Зачем

Экспортер обязан находиться в той же локальной сети, что и опрашиваемое устройство — это ограничение локального протокола, через интернет он не работает (см. `docs/REVERSE_ENGINEERING.md`). Если держать экспортер на устройстве, не подразумевающем бесперебойную работу, метрики пропадают всякий раз, когда устройство выключено.

Решение — вынести экспортер на отдельное **всегда включённое устройство** в домашней сети. Реалистичные варианты:
- Свободный порт на роутере (если он поддерживает установку пакетов — см. ниже)
- Raspberry Pi или похожий мини-компьютер
- Любой другой Linux-хост, который и так всегда включён (NAS, домашний сервер и т.д.)

## Вариант: роутер с поддержкой OpenWRT-пакетов (Entware)

Многие роутеры на базе Linux поддерживают установку пакетов через систему **Entware** — по сути, мини-Linux поверх штатной прошивки, с доступом по SSH и собственным пакетным менеджером `opkg`.

### Общие шаги

1. **USB-накопитель, отформатированный в ext4** (не FAT32/NTFS) — Entware ставится
   именно на него, встроенной памяти роутера обычно категорически не хватает.
2. **Включить поддержку пакетов** в веб-интерфейсе роутера (часто называется
   "OPKG"/"Open Package support" — ищи в разделе компонентов/обновлений прошивки).
3. **Установить Entware** — обычно требует явно указать архитектуру процессора
   роутера (mips/mipsel/aarch64/arm — зависит от модели) и **явно указать нужный
   диск** (флешку, а не встроенную память) при установке.
4. **Установить Python3** через `opkg` (не через `pip` с нуля — на слабых/нестандартных
   архитектурах вроде MIPS часть Python-пакетов требует компиляции через **Rust**,
   а Rust попросту не поддерживает многие встраиваемые архитектуры. Если видишь
   ошибку сборки с упоминанием `rustup`/`cargo`/`maturin` — ищи готовый
   **precompiled**-пакет той же библиотеки прямо в репозитории Entware через
   `opkg list | grep <имя>`, вместо того чтобы пытаться собрать через pip).
5. **Перенести `exporter.py`** на устройство.
6. **Настроить автозапуск.** У Entware свой формат init-скриптов — не совпадает с
   классическим OpenWRT (`/etc/rc.common` там нет). Скрипт подключает готовый
   `/opt/etc/init.d/rc.func`, который сам реализует `start`/`stop`/`restart` на
   основе переменных `PROCS`/`ARGS` в начале файла (см. пример
   `S99hobot-exporter` в этой папке). Имя файла должно начинаться с `S` и числа —
   число задаёт порядок запуска относительно других сервисов.

### Пример конфигурации

См. `S99hobot-exporter` в этой папке — скопируй в `/opt/etc/init.d/` на устройстве,
подставь свои `HOBOT_DEVICE_ID`/`HOBOT_DEVICE_IP`/`HOBOT_LOCAL_KEY`, дай права на
исполнение (`chmod +x`) и запусти (`/opt/etc/init.d/S99имя-файла start`).

## Проверка автозапуска

Проверь перезагрузкой устройства целиком (не просто перезапуском скрипта) —
некоторые системы автозапуска регистрируют сервис только при явном включении
соответствующей опции (например, `ENABLED=yes` в самом скрипте — уже включено
в примере).

## Что дальше

Сам по себе exporter на этом устройстве отдаёт метрики только внутри локальной
сети. Чтобы Prometheus (например, на VPS) мог их забирать откуда угодно —
устройству нужен ещё и WireGuard-клиент. См. `../docs/NETWORK_SETUP.md`.
