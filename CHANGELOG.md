## [1.2] — 2026-08-21

### Изменено
- **Prometheus и Grafana перенесены с локальной VM на VPS** — последняя зависимость
  от локальной VM убрана, вся инфраструктура теперь работает автономно.
- **WireGuard-туннель теперь Router ↔ VPS**, без промежуточного
  узла (VM) — роутер сам, как always-on устройство, устанавливает исходящее
  соединение к VPS через поддержку WireGuard.
- Grafana привязана к адресу VPS внутри туннеля (не к `0.0.0.0` и не к `127.0.0.1` — последний не работает из-за особенностей маршрутизации loopback-адресов в
  большинстве VPN-клиентов на базе TUN).
- Порт Prometheus больше не публикуется наружу (доступ только изнутри
  Docker-сети, при необходимости отладки — через SSH-туннель).
- Добавлены `mem_limit`/`cpus` на оба Docker-сервиса — жёсткий потолок ресурсов,
  чтобы не мешать другим сервисам на том же VPS.
- `scrape_interval` Prometheus увеличен с 15с до 60с — меньше нагрузка на диск и CPU.
- Добавлено правило на роутере, блокирующее прямой доступ из домашней сети к
  туннельной подсети — теперь доступ возможен **только** через VPN, независимо
  от физической сети подключения.

### Известные нюансы
- Docker и `ufw` не всегда совместимы "из коробки" — Docker управляет `iptables`
  напрямую и может обходить правила `ufw` для опубликованных портов. Надёжнее
  привязывать порты к конкретному IP (например, `127.0.0.1` или адресу
  внутри приватной сети), а не полагаться только на `ufw deny`.

## [1.1] — 2026-08-20

### Изменено
- **exporter перенесён с локальной VM на отдельное всегда включённое
  устройство в локальной сети.** См. `router/README.md`.
- `docker-compose.yml` больше не включает сервис `hobot-exporter` — теперь это
  отдельный, не-Docker деплой (см. `router/`).
- Добавлена ротация логов в самом `exporter.py` (через `HOBOT_LOG_FILE`,
  10 МБ × 3 файла).

### Известные нюансы
- На архитектурах вроде MIPS пакет `cryptography` через `pip` может не собраться
  из-за отсутствия поддержки Rust-компилятора для этой архитектуры — решение:
  ставить готовый прекомпилированный пакет через системный менеджер пакетов
  (`opkg`), а не через pip с нуля.

## [1.0-stable] — 2026-08-20

Первый полностью рабочий, стабильный релиз.

### Добыча данных
- Реверс-инжиниринг приложения Hobot Legee (APK) — определена реальная облачная
  платформа устройства (Tuya, SDK "Smart Life")
- Извлечены `app_id`/`app_secret`, `devId`, `localKey` пылесоса через перехват AES-расшифрованного трафика (Frida + рутованный Android-эмулятор)
- Подтверждён прямой локальный доступ к устройству через `tinytuya`, без облака

### Инфраструктура
- Python-экспортер (`exporter.py`) — опрашивает пылесос локально, отдаёт метрики в формате Prometheus
  - Заряд батареи, статус, площадь/время текущей уборки, код ошибки, онлайн-статус
  - Мерж частичных `dps`-обновлений с последним известным состоянием (устройство не всегда шлёт полный снимок за один опрос)
- Docker Compose стек: exporter + Prometheus + Grafana
  - Retention лимиты на Prometheus (90 дней / 2 ГБ)
  - Лимиты на логи всех контейнеров (json-file, 10MB × 3 файла)
  - Автозапуск контейнеров при перезагрузке VM (`restart: unless-stopped` + `systemctl enable docker`)
- Готовый дашборд Grafana с автоматическим provisioning (датасорс + сам дашборд)

### Сеть и доступ
- DHCP-резервация статических IP для пылесоса и VM на роутере
- Удалённый доступ к Grafana только через собственный VPN-туннель (Xray-based):
  - WireGuard-туннель VM ↔ VPS (обход CGNAT на домашнем интернете)
  - Правило маршрутизации в Xray, разрешающее приватную подсеть туннеля
  - Настройка VPN-клиента — полный TUN-режим, корректировка исключённых маршрутов

### Известные ограничения
- Единицы измерения площади уборки (`clean_area`) не подтверждены документацией Tuya — возможна неточность масштаба
- CPU/RAM самого устройства недоступны без физического вмешательства (UART/JTAG) — вне зоны действия текущего решения
- Часть `dps`-полей (карта, позиционирование, координаты дока) не расшифрована — оставлена как отдельная будущая задача
