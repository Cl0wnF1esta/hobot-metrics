# Как были добыты devId / localKey — методология

Этот документ описывает процесс, которым были получены учётные данные для локального
доступа к пылесосу Hobot Legee 7 (devId, localKey).

## Итог: платформа — Tuya (через SDK "Smart Life")

Несмотря на путаницу в процессе (в декомпилированном коде и в логах приложения
встречались следы Gizwits SDK), фактический облачный бэкенд, через который работает
Legee 7 — это **Tuya**, конкретно через встроенный SDK "Smart Life" / "ThingSmart".
Прямое тому подтверждение — MQTT-топик `tuya/smart/will`, увиденный в перехваченном
трафике, и API-методы вида `smartlife.m.user.email.password.login`.

## Шаги

### 1. Первичный реверс APK
- Скачан оригинальный `.xapk`
- Декомпилирован через `jadx` (CLI и GUI)
- В коде найдены признаки Tuya SDK (`com.thingclips.smart.*`, `ThingCertificatePinner`)
- В `assets/UIConfig.json` и `UIConfig.json.bak` найдены `app_id`/`app_secret`
  (публичные идентификаторы приложения в экосистеме Tuya, не пользовательские секреты)

### 2. Попытка прямого доступа через Tuya Cloud REST API — не сработала
- Аккаунт пылесоса не был виден через стандартный `/app/login` REST API Tuya
  ни с одним из найденных `app_id`
- Вывод: аккаунт создан/управляется через внутренний бинарный SDK-протокол
  приложения, а не через публичный REST API

### 3. Обход pinning через рутованный Android-эмулятор + Frida
- APK-патчинг (apk-mitm) не сработал — бэкенд проверяет подпись приложения
  (`ILLEGAL_CLIENT_ID` при пересобранном/переподписанном APK)
- Настроен рутованный Android-эмулятор (Android Studio, образ x86_64 с
  ARM-трансляцией, обязательно с 4KB page size — новые образы могут быть 16KB
  по умолчанию и не совместимы с нативными библиотеками старого приложения)
- Установлено **оригинальное** (непатченное) приложение в эмулятор
- Frida (`frida-server` на эмуляторе + `frida-tools` на хосте, версии должны совпадать)
  подключена к запущенному процессу приложения (через `-n`, не `-f` — spawn может не
  работать на некоторых сборках)

### 4. Перехват расшифрованного трафика
- Хук на `SSL_write`/`SSL_read` (`scripts/ssl_dump.js`) показал HTTPS-трафик в
  открытом виде, но полезные данные внутри JSON-ответов (`result`) оказались
  зашифрованы ещё одним слоем — AES на уровне приложения (поверх TLS)
- Хук на `javax.crypto.Cipher.doFinal` (`scripts/aes_dump.js`) перехватил
  сам момент AES-расшифровки в Java-коде — это дало полностью читаемый JSON
  с данными устройства, включая `devId` и `localKey`

### 5. Подтверждение через прямой локальный доступ
- `python -m tinytuya scan` нашёл устройство в локальной сети по `devId`
- Прямое подключение через `tinytuya.Device(devId, ip, localKey)` подтвердило
  рабочие credentials (`scripts/check_vacuum.py`)

## Если понадобится повторить процедуру

Основные компоненты для повтора:
1. `scripts/ssl_dump.js` и `scripts/aes_dump.js` — Frida-скрипты для перехвата
2. Тот же рутованный эмулятор с ARM-трансляцией и 4KB page size
3. Оригинальный (непатченный) APK/XAPK приложения Hobot
