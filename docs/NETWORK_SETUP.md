# Сетевая часть: доступ к Grafana только через VPN

## Проблема

Домашний интернет может быть за **CGNAT** (провайдер не выдаёт настоящий публичный IP) —
в этом случае классический проброс портов через роутер не работает в принципе: снаружи
физически нет адреса, до которого можно достучаться напрямую.

Проверить это просто: сравни IP, который твой роутер показывает как "внешний" в своей
админ-панели, с тем, что показывает любой сервис вида "какой у меня IP" при заходе с
устройства **вне** домашней сети (например, с мобильного интернета). Если они не
совпадают — ты за CGNAT.

## Решение: собственный VPS как точка входа

Если у тебя уже есть свой VPS с любым VPN-сервером на базе Xray-core (X-UI, 3x-ui,
Marzban и т.п.) — не нужно пытаться пробить CGNAT, вместо этого строим **исходящий**
(от дома к VPS) WireGuard-туннель. Домашнее устройство само инициирует соединение
наружу — это всегда работает, независимо от CGNAT.

```
Твоё устройство → VPN-клиент (полный TUN-режим) → VPS
                                                     │
                                                     │ (правило роутинга:
                                                     │  подсеть туннеля → direct)
                                                     ▼
                                               WireGuard-туннель
                                                     │
                                                     ▼
                                          Домашняя машина → Grafana:3000
```

Без включённого VPN — адрес домашней машины внутри туннеля недостижим вообще (это
приватный IP, не существующий в публичном интернете). С включённым VPN — трафик идёт
через VPS, у которого есть прямой доступ к этой подсети.

## Компоненты

### 1. WireGuard-туннель (VPS ↔ домашняя машина)

Пример адресации (замени на свою собственную приватную подсеть, не занятую в другом
месте твоей инфраструктуры):
- VPS: `10.10.10.1/24`, слушает `51820/UDP`
- Домашняя машина: `10.10.10.2/24`, инициирует исходящее соединение к VPS

`PersistentKeepalive = 25` на стороне домашней машины — обязательно, иначе NAT-маппинг
у провайдера протухнет, и VPS не сможет достучаться в обратную сторону, даже если
домашняя машина может достучаться до VPS.

Конфиги — `/etc/wireguard/wg0.conf` на обеих машинах. **Не хранить в git** — содержат
приватные ключи.

### 2. Правило маршрутизации в Xray (на VPS)

По умолчанию большинство панелей на базе Xray (X-UI, 3x-ui и аналоги) блокируют любые
приватные IP-адреса как destination — это защита от SSRF-атак. Нужно добавить
исключение **выше** правила блокировки (обычно выглядит как `geoip:private` →
`blocked`/`block`) в конфиге роутинга (`routing.rules`):

```json
{
  "type": "field",
  "ip": ["10.10.10.0/24"],
  "outboundTag": "direct"
}
```

(подставь свою подсеть туннеля вместо примера, и название `outboundTag`, соответствующее
"прямому" outbound в твоей конкретной конфигурации — обычно `direct` или `freedom`)

### 3. Настройки VPN-клиента на устройстве, с которого заходишь

VPN-клиенты на базе Xray-core (v2rayNG, NekoBox, Happ, sing-box-based клиенты и т.д.)
обычно имеют **собственный** список "исключённых маршрутов" на уровне системного
VPN-интерфейса (Android VpnService route table / аналог на других платформах) —
это отдельный механизм от роутинга на сервере. По умолчанию туда часто попадает весь
диапазон `10.0.0.0/8` целиком, что может перекрыть и подсеть твоего туннеля, если она
из этого диапазона.

Нужно найти в настройках клиента список исключённых/обходимых VPN маршрутов (может
называться "Bypass LAN", "Исключённые маршруты", "Private network bypass" и т.п.) и
убрать/сузить исключение так, чтобы подсеть туннеля из него не попадала.

Также стоит убедиться, что клиент работает в режиме **полного системного туннеля**
(часто называется TUN mode / VPN mode), а не как локальный прокси — иначе
маршрутизация на произвольные IP-адреса (вроде адреса домашней машины в туннеле)
может не работать вообще, независимо от остальных настроек.

## Диагностика, если не работает

1. Проверь связность самого WireGuard-туннеля независимо от VPN-клиента:
   `ping` в обе стороны между VPS и домашней машиной, `wg show` на обеих сторонах —
   должна быть свежая `latest handshake`.
2. Если туннель работает, но VPN-клиент всё равно не видит домашнюю машину —
   проверяй по очереди: правило роутинга на VPS → список исключённых маршрутов на
   клиенте → включён ли режим полного туннеля на клиенте.

## На будущее

- Если IP домашней машины/устройства в локальной сети сменится — стоит настроить
  DHCP-резервацию на роутере, чтобы этого не происходило.
- Если VPS сменится/переустановится — WireGuard-туннель и правило в Xray нужно
  настраивать заново.
